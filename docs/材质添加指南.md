# 材质添加指南

本指南说明如何为本材质包添加新材质。项目自带导入脚本 `tools/add_texture.py`，**绝大多数情况下你只需要准备 PNG，其余文件由脚本生成**。

---

## 一、先理解原理：四层文件的关系

一个带材质的 Slimefun 物品，最终由四个环节串起来：

```
物品 ID ──(清单)──> 模型 ──(layer0)──> 贴图
             │
             └─(生成)──> 分发定义：按物品 ID 决定“用谁的模型”
```

| 层级 | 位置 | 作用 | 谁维护 |
|---|---|---|---|
| **贴图** | `assets/<附属>/textures/<子目录>/<id>.png` | 画面 | 脚本拷贝 / 你手动放 |
| **模型** | `assets/<附属>/models/<子目录>/<id>.json` | 指定用哪张贴图 | 脚本生成 |
| **清单** | `data/itemdefs/<基底>.json` | 记录“哪个物品 ID 用哪个模型” | 脚本追加，**这是唯一的注册表** |
| **分发定义** | `assets/minecraft/items/<基底>.json` | 客户端按物品的 `custom_data` 选模型 | 脚本生成，**不要手改** |

术语统一如下：

- **附属**：命名空间，即 `assets/` 下的目录名，如 `slimefun`、`infinityexpansion`。
- **基底**：原版物品，如 `apple`、`netherite_sword`、`chest`。Slimefun 用原版物品承载自定义物品，所以必须先挑一个基底。
- **条目**：清单里的一条 `{ "id", "model" }`，代表一个 Slimefun 物品。
- **匹配键**：物品 `custom_data` 里的 `PublicBukkitValues.slimefun:slimefun_item`，值为条目 ID。

命中时显示自定义模型；没有命中就回退到清单里的 `tail`（通常是原版自身模型），所以原版物品不会掉材质。

## 二、添加一个普通物品材质（5 步）

以物品 ID `SHINY_CRYSTAL`、苹果基底为例：

**第 1 步：准备图片**

把 PNG 放进 `tools/import/`（脚本首次运行会自动创建，支持子目录），**文件名就是 Slimefun 物品 ID**：

```
tools/import/SHINY_CRYSTAL.png
```

> 命名规则：大写字母开头，只能含 `A-Z`、`0-9`、`_`。小写文件名会被自动转大写并提示。

**第 2 步：运行脚本**

```
python tools/add_texture.py
```

按提示依次选择：附属 → 类型（`item`） → 基底（如 `apple`） → 资源子目录（回车用推荐值）。

也可以一条命令直达：

```
python tools/add_texture.py --addon slimefun --type item --base apple --dir slimefun/items
```

**第 3 步：确认脚本做了什么**

以物品 ID `SHINY_CRYSTAL` + 子目录 `slimefun/items` 为例，脚本会写入：

```
assets/slimefun/textures/slimefun/items/shiny_crystal.png      ← 贴图
assets/slimefun/models/slimefun/items/shiny_crystal.json       ← 模型（默认 parent: item/generated）
data/itemdefs/apple.json                                       ← 追加 {"id":"SHINY_CRYSTAL","model":"slimefun:slimefun/items/shiny_crystal"}
assets/minecraft/items/apple.json                              ← 重建分发定义
```

生成的模型是单行紧凑 JSON：

```json
{"parent":"item/generated","textures":{"layer0":"slimefun:slimefun/items/shiny_crystal"}}
```

**第 4 步：校验**

```
python tools/add_texture.py --verify --no-pause
```

输出 `异常 0 个` 即表示清单与产物一致。

**第 5 步：进游戏**

客户端按 `F3+T` 重载资源包（或重启客户端）。

## 三、三类常用材质

| 类型 | 适用场景 | 关键要素 | 与普通物品的差别 |
|---|---|---|---|
| **普通物品** | 材料、食物、零件、机器图标 | PNG + 模型（`item/generated`） | — |
| **动态物品** | 发光、旋转、脉冲类特效图标 | PNG **帧条** + 同名 `.png.mcmeta` | 贴图旁多一个 mcmeta，脚本不负责 |
| **方块类物品** | 机器外壳、压缩方块、染色方块 | 方块基底 + 模型（平面或立体） | 模型 parent 可能要换成 `block/*` |

### 3.1 普通物品（含工具）

- **平面图标**：`parent` 用 `item/generated`，一层 `layer0` 即可，脚本默认就是这个。
- **手持工具**（剑、镐、斧、锹、锄）：建议把模型 `parent` 改成 `item/handheld`，否则手持时的角度不像工具：

```json
{"parent":"item/handheld","textures":{"layer0":"bump:magical_weapons/bone_sword"}}
```

> 脚本一律写 `item/generated`，需要手持角度时手动改这一个字段即可，改完**不用**重跑脚本，分发定义不关心 `parent`。

- 贴图尺寸建议 16×16 起步、保持正方形；放大 32、64 也可以，但同一附属内尽量统一。

### 3.2 动态物品（动画贴图）

动画的本质是**一张竖排帧条**：宽度 = 单帧宽，高度 = 单帧高 × 帧数，帧从上到下排列。

关键要素只有两个，缺一不可，且必须同名同目录：

```
assets/<附属>/textures/<子目录>/<id>.png          ← 帧条
assets/<附属>/textures/<子目录>/<id>.png.mcmeta   ← 动画参数
```

最简单的 mcmeta（每帧停留 2 tick，即 0.1 秒）：

```json
{"animation":{"frametime":2}}
```

需要插值或指定播放顺序时：

```json
{"animation":{"interpolate":true,"frametime":6,"frames":[0,1,2,3,2,1,0]}}
```

仓库中的真实例子：`assets/infinityexpansion/textures/machines/infinity_workbench_side.png.mcmeta`。

注意事项：

- **脚本只拷贝 PNG**，`.png.mcmeta` 需要你手动放到贴图旁边；流程是「先跑脚本生成 PNG 与模型 → 再放 mcmeta」。
- 文件名必须完全对应，写成 `xxx.png.png.mcmeta` 或 `xxx.mcmeta` 都不会生效。
- 动画作用于**贴图**，所以多个条目共用同一张贴图时会一起动；要给不同物品不同动画就各用各的贴图。
- `frames` 可省略（默认 0,1,2…顺序播放）；帧数越多贴图越高（仓库里有 36 帧、64×2304 的例子），注意文件体积。

### 3.3 方块类物品

选基底时用 `--type block`，脚本会把候选基底筛成方块类（箱子、熔炉、羊毛、玻璃等）。**但这只影响菜单归类，不影响产物结构。**

- 方块基底的 `tail` 一般是方块模型，例如 `blast_furnace` 的清单尾部是 `block/blast_furnace`，未命中时正确显示原版方块物品。
- **平面图标**：保持脚本默认的 `item/generated` 即可，仓库里大多数机器图标都是这样。
- **立体图标**（想要“一个方块”的观感）：手动把模型换成方块模型，例如：

```json
{"parent":"block/cube_all","textures":{"all":"infinityexpansion:materials/machine_core"}}
```

  名字带朝向的机器可用 `block/orientable` 等 parent，此时 `textures` 需要写 `top`/`front`/`side` 等多个键。

注意事项：

- 本包**没有 `blockstates/`，也没有 `assets/minecraft/models/block/`**，所以它只改变物品栏/手持的图标，**不改变方块放在世界里的外观**。
- 立体图标的贴图是立方体的单面纹理（通常 16×16），六面共用，不要直接拿带透视的平面图。

### 3.4 头颅（本包数量最多的一类）

- 类型选 `head`，基底固定为 `player_head`，不用挑基底，PNG 命名规则与物品一致。
- 头颅条目用的仍是平面图标模型（`item/generated`），`player_head` 的 `tail` 是原版头颅的特殊模型。
- 1.21.6+ 需要一份 overlay 版本（清单里的 `tail_overlay`），脚本会自动同步重建：

```
overlay_1_21_6_plus/assets/minecraft/items/player_head.json
```

- 目前自动重建 overlay 的只有 `player_head`。`overlay_.../items/` 下的工具类文件（各材质剑、镐、斧等）是历史手工产物，改这些基底的清单**不会**自动同步 overlay —— 忘了同步就会出现「1.21.6+ 显示旧材质或错材质」（例如下界合金镐变钻石镐就是因为 overlay 的回退写错了）。改完请检查对应 overlay 文件的 `fallback` 是否指向自身，或直接跑一次 `--verify`。

## 四、关键要素与相互关系

| 要素 | 写法 | 与其他要素的关系 |
|---|---|---|
| 物品 ID | `SHINY_CRYSTAL` | 匹配键的值；决定文件名（转小写） |
| 清单条目 | `{"id":"SHINY_CRYSTAL","model":"slimefun:slimefun/items/shiny_crystal"}` | `model` 指向模型路径，必须能解析到 `assets/<ns>/models/<path>.json` |
| 模型 | `{"parent":"item/generated","textures":{"layer0":"slimefun:.../shiny_crystal"}}` | `layer0` 指向贴图，必须能解析到 `assets/<ns>/textures/<path>.png` |
| 贴图 | `shiny_crystal.png` | 文件名 = 模型 `layer0` 的最后一段 |
| 分发定义 | `assets/minecraft/items/<基底>.json` | 由清单+基底自动生成，负责“哪个 ID 用哪个模型” |

三条硬约束：

1. `model` 与 `layer0` 里的命名空间必须真实存在于 `assets/` 下。
2. 同一个物品 ID **只能注册在一个基底**里。脚本发现该 ID 已在别的基底会跳过，换基底重导不会生效。
3. 基底清单必须是 `"generated": true`；`generated: false` 的基底是手工维护，脚本拒绝写入。

---

## 五、注意事项清单

- **不要手改生成物**：`assets/minecraft/items/<基底>.json` 每次重建都会覆盖；要改就改清单或模型。
- **匹配是"全等"比较**：客户端比的是整个 `custom_data` 组件。物品被写入任何额外 PDC 数据（如附属的 `last_used` 冷却）后，整棵树不再相等，材质会掉回原版。这属于已知限制，材质包侧无法通配。
- **同一 ID 重复导入**只更新贴图，模型路径与清单条目保持不变。
- **`--no-rebuild`** 只写贴图/模型/清单，不重建分发定义；忘了去参数会导致游戏内看不到变化。
- **新增基底**：在 `data/itemdefs/` 新建清单（`base`、`generated: true`、`entries: []`、`tail` 指向原版模型），再跑脚本或直接手动补 `assets/minecraft/items/<基底>.json`，否则 `--verify` 会报“缺少产物”。
- **文件编码与格式**：JSON 用 UTF-8、2 空格缩进（模型可用单行紧凑格式），不要加 BOM。
- **物品数量多时**：脚本会在 `condition` 链与 `select` 之间自动切换（Gson 嵌套上限 255，脚本留余量到 250），不要去手动调结构。
- **贴图更新后**客户端需 `F3+T` 重载；服务器分发资源包时要重新打包上传。

## 六、校验与排错

```
python tools/add_texture.py --verify --no-pause     # 校验清单与产物一致
python tools/add_texture.py --help                  # 查看全部参数
```

| 现象 | 常见原因 | 处理 |
|---|---|---|
| 游戏内还是原版材质 | 未重建分发定义 / 客户端没重载 | 去掉 `--no-rebuild` 重跑，`F3+T` |
| 模型丢失（紫黑格） | `model` 或 `layer0` 路径写错、文件不存在 | 按清单里的路径逐级核对文件是否真实存在 |
| 贴图丢失但模型正常 | 模型 `layer0` 指向的 PNG 不存在 | 检查模型 JSON 的 `layer0` 与贴图文件名是否一致 |
| 换基底重导没反应 | 该 ID 已注册在另一个基底 | 到原基底上重导，或先删掉旧条目 |
| 动画不播放 | 缺少 `.png.mcmeta`、文件名不匹配、帧条不是竖排 | 对照 3.2 的两文件同名单目录规则 |
| 手持角度不对 | 模型用了 `item/generated` | 改成 `item/handheld` |
| 使用一次后材质消失 | 物品 PDC 被写入额外数据（如 `last_used`） | 见第五节「匹配是全等比较」 |
| 1.21.6+ 显示的还是旧材质 | overlay 未同步 | 检查 `overlay_1_21_6_plus/.../items/<id>.json` |

## 七、命令速查

```
# 交互式（推荐日常使用）
python tools/add_texture.py

# 物品：附属 slimefun、苹果基底、资源子目录 slimefun/items
python tools/add_texture.py --addon slimefun --type item --base apple --dir slimefun/items

# 方块：箱子基底
python tools/add_texture.py --addon fluffymachines --type block --base chest --dir machines

# 头颅：基底固定 player_head，无需 --base
python tools/add_texture.py --addon slimefun --type head --dir slimefun/items

# 只更新贴图，不重建分发定义
python tools/add_texture.py --addon slimefun --type item --base apple --dir slimefun/items --no-rebuild

# 自动化/脚本调用：结束不停留
python tools/add_texture.py --verify --no-pause
```
